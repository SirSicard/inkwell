# S3.4 checklist: the ink and the Drop on the desktop

What an SSH session cannot check. Over SSH there is no compositor: the Drop's swapchain cannot be
made there (DXGI says "not currently available"), and the frame clock falls back to a sleep. So
whether keystrokes stay in another app, and how the ink looks and moves on screen, need you at
the PC. About 10 minutes. Note the date, the Windows build and the commit under Result.

## Build it

In a terminal at the PC, from the repository:

```
cd core
cargo build -p ink-ffi --lib
cd ..\windows
dotnet publish Inkwell\Inkwell.csproj -c Release -o %TEMP%\inkwell-app
```

## The tests that need a desktop

Still in `windows\`:

```
dotnet test Inkwell.Ink.Tests\Inkwell.Ink.Tests.csproj --filter FullyQualifiedName~DropTests
```

- [ ] 3 passed, 0 skipped. Over SSH `TheDropDrawsWhileLiveAndNothingWhileHidden` is skipped for
      want of a compositor; at the desktop it must run and pass. A small paper panel flashes at the
      bottom of the screen while it runs: that is the test.

## Typing while the Drop cycles

- [ ] Open Notepad with a new document.
- [ ] Start Inkwell with the Drop cycling through its states, one every 3 seconds, and your
      library kept out of it:

      set INK_DROP_DEMO=3
      set INK_DATA_DIR=%TEMP%\inkwell-check
      %TEMP%\inkwell-app\Inkwell.exe

      The cycle is dictating, meeting, blotting, problem, then idle (the Drop hides), and again.
- [ ] Inkwell's window opens at launch and takes focus once, as any app does when started. Close
      it with its X (it goes to the tray) or leave it; then click into the Notepad document.
- [ ] Type continuously for at least two full cycles (about 30 seconds): every character lands in
      Notepad, and none is lost as the Drop appears, changes or hides.
- [ ] Notepad's title bar stays active (not greyed) and its caret keeps blinking throughout.
- [ ] The taskbar keeps Notepad highlighted; Inkwell's Drop never gets a taskbar button.
- [ ] The Drop sits at the bottom centre of the screen you are working on, above the taskbar's
      edge and above other windows, and shows each state: "Dictating / Listening", "● REC /
      Recording this meeting" (the title in red), "Blotting / The final pass", "Far end silent /
      Nothing is arriving from the call" (red title and red border), then disappears.
- [ ] Alt-Tab: the Drop is never in the list.

## Clicking the Drop

- [ ] While the Drop shows, click on it (the ink and the text). Notepad stays active and its
      caret keeps blinking; typing afterwards still lands in Notepad.

## Narrator

The Drop tells screen readers what it shows, as VoiceOver hears the Mac's: its title and its
second line, read out at each change without the Drop taking focus.

- [ ] Start Narrator (Ctrl+Win+Enter), start Inkwell with `INK_DROP_DEMO=3` as above, close its
      window with its X and click into the Notepad document. As each state appears Narrator says
      it once, unasked, after whatever it was saying: "Inkwell: Dictating, Listening", "Inkwell:
      ● REC, Recording this meeting" (it may name the dot or skip it), "Inkwell: Blotting, The
      final pass", "Inkwell: Far end silent, Nothing is arriving from the call". Nothing is said
      when the Drop hides. Typing still lands in Notepad and its caret keeps blinking. Note
      whether Narrator keeps up with the 3-second cycle. Stop Narrator with Ctrl+Win+Enter.

## Full screen and another screen

- [ ] Put a browser in full screen (F11) and click into its address bar: the Drop shows over it
      and typing stays in the address bar. (A game in exclusive full screen may cover it; that is
      Windows' rule for exclusive full screen, not a failure.)
- [ ] If you have a second monitor: click into Notepad on it; the Drop's next appearance is on
      that monitor, sized for its scaling.

## Motion

- [ ] Settings > Accessibility > Visual effects > Animation effects **off**: within a few seconds
      the Drop's ink (and the ink in Inkwell's window) shows each state as a still drop and does
      not move. Turn it back **on**: the ink moves again while the Drop shows. No restart needed.

## Losing the graphics device

The Drop is the recording indicator: it must never go blank. Start Inkwell with
`INK_DROP_DEMO=3` again and let it cycle while you do each of these (both need an administrator
terminal):

- [ ] **Force a TDR (a GPU reset) while the Drop shows:** `dxcap -forcetdr`. dxcap comes with
      Windows' optional "Graphics Tools" feature; if `dxcap` is not found, skip this line and note
      "no dxcap" (installing it is your call, it is not needed otherwise). The screen blinks; within
      a few seconds the Drop is back with its moving ink. In between it may show a plain panel
      (a black dot, the state's two lines): that is its fallback, never nothing.
- [ ] **Restart DWM while the Drop shows:** `taskkill /f /im dwm.exe` (Windows restarts it at
      once; the screen flickers). Within a few seconds the Drop is back with its moving ink, or
      shows its plain panel meanwhile, and typing in Notepad still lands there.
- [ ] While the plain panel shows, hovering the tray icon says "Inkwell. The Drop: couldn't ...",
      and Inkwell's window (open it from the tray) says "The Drop: couldn't ..." beside the core's
      status; both go back to plain when the ink is back.
- [ ] With Animation effects **off**, do the DWM restart again: the Drop notices within about a
      second even though its ink is still, shows the plain panel, and comes back.

## The look

Compare with the Mac's Drop if you can, or with the design canvas.

- [ ] Paper panel, 16-point rounded corners, a hairline border; the ink on the left fading into
      the paper at its right edge, with no seam and no straight edge cutting the blob.
- [ ] Text crisp at your display scaling, in Segoe UI Variable: a small grey title over a
      darker line.
- [ ] Inkwell's own window shows a small ink (above the "Inkwell" title, until the screens give
      it its place) in the same state as the Drop.
- [ ] There is no drop shadow under the Drop (the Mac's panel has one). Say whether you want one.
- [ ] The wordmark face: Windows has no "Segoe UI Variable Display Black" (Segoe UI Variable
      stops at Bold), so the wordmark uses Segoe UI Black. It shows only where the screens put
      the wordmark (Today); if you want to see it now, say so and it can be switched on in the
      window's ink.
