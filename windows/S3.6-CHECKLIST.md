# S3.6 checklist: the Windows installer and updates, on the desktop

What an SSH session cannot check: the installer's windows, SmartScreen, the Start menu, the app
installed and running in your session, an update applied and restarted, and an uninstall. About
thirty minutes at the PC, signed in. Note the date, the Windows build and the commit under Result.

The installer writes outside the build folders (your Start menu, Settings > Apps, and
`%LOCALAPPDATA%\InkwellApp`), which is why this is yours to run. It never touches the library
folder, `%LOCALAPPDATA%\Inkwell`.

Automated checks cover the logic behind each line: `windows/scripts/build-core.ps1` (the core's
DLL needs no Visual C++ runtime, delay-loads Vulkan for only the functions it lists and the
diarizer's DLL, and starts on a PC without Vulkan: `tests/vulkan_missing.rs`; the engines' DLLs and
the Visual C++ runtime DLLs they import sit beside it), `windows/scripts/pack.ps1` (the package is
x64's; every DLL any binary loads is beside `Inkwell.exe` or part of Windows, ONNX Runtime the app's
own and never Windows' copy in System32, the Visual C++ runtime the x64 copy beside `Inkwell.exe`
and of one version; the feed's size and SHA-256 are the package's), `dotnet test` (`UpdatesModelTests` for the updates row, `AboutModelTests` and
`NoticesTests` for the copyright line, the terms and Velopack's notice, `TermsStepTests` for the
first run's terms step), `windows/scripts/tests/test-release-version.sh` and
`windows/scripts/tests/test-dll-imports.ps1`.

## Setup

Two folders of release files, built from this branch: `<release>` with the 1.0.0 installer and
its checksums, and `<release-1.0.1>` with a 1.0.1 package, for the update in section 4. The step's
report says where they are on the PC; to make them yourself, run docs/RELEASING.md's commands for
a PC twice, with 1.0.0 and 1.0.1. Both are unsigned test builds of the same code; only the version
differs. (Once this is merged, a dry run of `win-release.yml` makes the same files in CI.)

- [ ] Copy `<release>\Inkwell_1.0.0_x64-setup.exe` to your Downloads folder, and mark it
      as downloaded from the internet, as a browser would, so SmartScreen treats it as it will
      treat a real download (PowerShell):

      ```powershell
      Set-Content -Path "$HOME\Downloads\Inkwell_1.0.0_x64-setup.exe" -Stream Zone.Identifier -Value "[ZoneTransfer]`r`nZoneId=3"
      ```

- [ ] Nothing called Inkwell is in Settings > Apps > Installed apps, and there is no
      `%LOCALAPPDATA%\InkwellApp` folder. If `%LOCALAPPDATA%\Inkwell` exists (your library from the
      earlier checklists), note roughly what is in it: it must be the same at the end, but for
      `terms-agreed.txt` (the first run's agreement to Microsoft's terms).

## 1. The homepage's steps (windows/HOMEPAGE-INSTALL.md)

- [ ] `Get-FileHash -Algorithm SHA256 "$HOME\Downloads\Inkwell_1.0.0_x64-setup.exe"` prints the hash
      on the installer's line of `<release>\Inkwell_1.0.0_windows-sha256.txt`.
- [ ] Double-click it. SmartScreen: "Windows protected your PC", publisher "Unknown publisher". The
      labels are **More info**, then **Run anyway**, as the homepage text says (note any that differ).
- [ ] No administrator prompt. A splash titled **Installing Inkwell**, with the paragraph on
      Microsoft's terms, sharp and whole. Note roughly how long it stays up, and whether that is
      long enough to read it. Then Inkwell opens by itself, on **Microsoft's terms**.
- [ ] Microsoft's terms: the same paragraph, then **Windows App SDK, by Microsoft**, **Windows SDK
      projection for .NET, by Microsoft** and **Visual C++ runtime, by Microsoft**, each opening onto
      its licence in full, and **Quit** and **Agree**. Nothing else of Inkwell is up: no main window,
      no tray icon.
- [ ] **Quit**: Inkwell exits (Task Manager shows no Inkwell.exe). Start it from the Start menu:
      the terms again. Close that window with its X: it exits the same way. Start it once more.
- [ ] **Agree**: the main window opens, with the first run's sheet over it, and the tray icon
      appears. Quit from the tray and start it again: no terms this time.
- [ ] If Smart App Control is on for this PC (Windows Security > App & browser control), note what
      it did instead. Do not turn it off for this.
- [ ] The browser's download warning (homepage step 1). Setup above skips the browser, so this
      needs the installer on a GitHub release: once a draft release carries the Windows files
      (the first tag), download the installer from it in Edge, and in Chrome if you use it. Edge:
      the download's **…** menu, **Keep**, then **Show more** and **Keep anyway**. Chrome: **Keep**.
      Note any label or message that differs, or that no warning appeared.

## 2. Installed

- [ ] Start menu: **Inkwell**, with Inkwell's icon; it starts the app (quit it from the tray first).
      No desktop shortcut.
- [ ] Settings > Apps > Installed apps: **Inkwell**, version 1.0.0, publisher Inkwell.
- [ ] The app lives in `%LOCALAPPDATA%\InkwellApp` (`current\Inkwell.exe`, `Update.exe`). The library
      is still `%LOCALAPPDATA%\Inkwell`: Settings > Storage shows that folder.
- [ ] Settings > About: **Inkwell 1.0.0**, and under it **Copyright (c) 2026 Mattias Hjemgaard**.
      Then **Check Now**. Then **TERMS**: the paragraph on Microsoft's terms, the same as on the
      first run, naming both components. Under CODE THAT SHIPS INSIDE INKWELL: **Velopack, by
      Velopack Ltd and Caelan Sayler (MIT)**, opening onto its licence.
- [ ] **Check Now**: "Checking for updates…", then "Inkwell is up to date." (No release carries a
      Windows feed yet, so there is nothing newer.) Narrator reads the new line without moving focus.
- [ ] With the network off (airplane mode), **Check Now** says "Couldn't check for updates: …" with
      a reason, and the button stays. Network back on.
- [ ] One dictation into Notepad works as in S3.5a (the installed build is the same app).
- [ ] With the Parakeet model downloaded, words appear in the Drop while you dictate: sherpa-onnx
      runs on the ONNX Runtime installed beside `Inkwell.exe` (`current\onnxruntime.dll`), not on
      Windows' older copy. And one meeting with two or more people on the far end tells their
      voices apart (the diarizer, `current\nemo_speech_asr_c.dll` and its ggml DLLs).

## 3. Without Vulkan (optional: needs a PC or VM with no GPU driver)

Skip it if you have no such machine; `tests/vulkan_missing.rs` covers the core in CI. On a PC or VM
without a Vulkan driver (Windows Sandbox is one, but turning it on is a Windows feature change, so
only if you want it):

- [ ] The installer runs and the app starts (no "vulkan-1.dll was not found" dialog, no "the core
      did not start").
- [ ] A dictation works, slowly (the CPU, about 1.6 s after letting go on this PC's CPU; not a
      measurement).
- [ ] A meeting records and finishes; the far end's speakers are not told apart (the diarizer needs
      the Vulkan loader), and the rest of the record is there.
- [ ] No Visual C++ Redistributable was installed on it (Settings > Apps shows none), yet the app ran.

## 4. An update, applied

The 1.0.1 package stands in for a release: Velopack's own updater applies it exactly as the app's
Restart to Update would, after the in-app download.

- [ ] Quit Inkwell (tray > Quit). Then (PowerShell):

      ```powershell
      & "$env:LOCALAPPDATA\InkwellApp\Update.exe" apply --package "<release-1.0.1>\InkwellApp-1.0.1-full.nupkg"
      ```

- [ ] Inkwell starts again by itself. Settings > About: **Inkwell 1.0.1**. Settings > Apps shows
      1.0.1.
- [ ] The library is untouched: Today and the Library show what they showed before, settings kept.

## 5. Uninstall

- [ ] Settings > Apps > Installed apps > Inkwell > **Uninstall**: a short progress window, then a
      message that it was uninstalled.
- [ ] The Start menu entry is gone, and Inkwell is gone from Settings > Apps.
- [ ] `%LOCALAPPDATA%\InkwellApp` is gone (it may take a few seconds: the updater deletes itself last).
- [ ] `%LOCALAPPDATA%\Inkwell`, the library, is still there, as noted in Setup.
- [ ] Reinstall and uninstall once more with the silent switches, from PowerShell, as an admin would
      script it: `& "$HOME\Downloads\Inkwell_1.0.0_x64-setup.exe" --silent` (installs and starts
      Inkwell; quit it), then `& "$env:LOCALAPPDATA\InkwellApp\Update.exe" --uninstall --silent`.
      Same result as above.

## Known limits (not failures)

- **Unsigned.** SmartScreen warns, and Smart App Control blocks the installer outright (Microsoft
  offers no per-app exception). `Update.exe` is unsigned too. Signing is a later step.
- **Updates only when asked.** There is no automatic check (the Mac asks before its first one;
  Windows has only Check Now for now). A check asks GitHub's API for the latest releases
  (unauthenticated: 60 an hour per address).
- **The installer's terms are a splash, not a page.** Velopack's Setup has no licence page or
  button to agree, only an image shown while it installs: Microsoft's terms are on it, in the
  release notes and on the download page, and in full in Settings > About. A `--silent` install
  shows no splash; the first run asks for the agreement either way.
- **No Windows calendar.** The calendar needs package identity (MSIX); this installer is not a
  package, so Up next says there is no calendar, as in the earlier checklists.
