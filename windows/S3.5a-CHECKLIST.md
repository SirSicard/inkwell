# S3.5a checklist: dictation end to end on the desktop

What an SSH session cannot check: the keyboard hook in your session, the microphone, pasting into
other apps, and the Drop on screen. About forty minutes at the PC, signed in. Note the date, the
Windows build and the commit under Result.

Automated checks cover the logic behind each line: the chain on mocks (`cargo test -p
ink-pipeline --test dictation_takes`: a second press never wipes the take, the 180 s watchdog,
voice edit, live words, the mode picked by the foreground process's executable), dictation through
the core on the mock platform and its consents (`cargo test -p ink-ffi --test voice`), Windows'
platform wired into the core with right Ctrl as the default (`cargo test -p ink-ffi`, which on
Windows runs `voice_win` and the clock test), and the shell's side (`dotnet test`: `DropModelTests`
for what the Drop says and when, `LevelTests` and `BandsTests` for the ink's levels, `DropTests`
for the live words' layout).

## Setup

In a **Developer Command Prompt for VS** (x64), from the repository. The core is built with its
engines: Qwen3-ASR on Vulkan (the CPU where there is no Vulkan GPU) and Silero VAD.

```
cd core
set LIBCLANG_PATH=C:\Program Files\LLVM\bin
set CMAKE_GENERATOR=Ninja
cargo build --release -p ink-ffi --lib --features engine-llama,ink-engines/engine-llama-vulkan,ink-engines/engine-silero
cd ..\windows
dotnet publish Inkwell\Inkwell.csproj -c Release -o %TEMP%\inkwell-app -p:InkCoreDir=%CD%\..\core\target\release\
```

Stage the dictation models from the bench data into a models folder, in Git Bash (Git for
Windows copies the files, about 2.4 GB; nothing is downloaded):

```
INK_BENCH_DIR=<bench data> scripts/stage-dictation-models.sh <models folder>
```

Start it on a scratch library with those models:

```
set INK_DATA_DIR=%TEMP%\inkwell-dictation
set INK_MODELS_DIR=<models folder>
%TEMP%\inkwell-app\Inkwell.exe
```

## 1. The key (the keyboard hook)

- [ ] From a terminal at the desktop: `cargo test -p ink-ffi --test voice_win -- --ignored`
      (in `core`): 1 passed. It holds right Ctrl through the real hook and lets go.
- [ ] Settings > Voice reads "Hold Right Ctrl, speak, let go." on a fresh library (no key chosen).
- [ ] A quick tap of right Ctrl types nothing and shows nothing. Left Ctrl shortcuts (Ctrl+C,
      Ctrl+V) work as usual in Notepad. (Right Ctrl+C does not copy while right Ctrl is the key:
      a known limit.)
- [ ] Settings > Voice > Dictate: **Right Alt**. At once: right Ctrl is ordinary again, holding
      right Alt dictates, and letting go opens no menu in Notepad. Pick **Right Ctrl** again.
- [ ] Settings > Voice: switch dictation off. Right Ctrl is an ordinary key. Quit (tray) and start
      again: it stays off. Switch it on: right Ctrl dictates again at once.

## 2. Dictating into Notepad, and the Drop

- [ ] New Notepad document, caret in it. Hold right Ctrl, say a sentence of about three seconds.
      Windows' microphone-in-use icon appears in the notification area.
- [ ] While held (from about 0.2 s): the Drop at the bottom centre reads "Dictating · Notepad ·
      Default" over "Listening" (live words need a live-partials engine, which this build does
      not have yet). **The ink moves with your voice**: louder speech, bigger motion; a pause,
      stillness.
- [ ] Let go: "Transcribing", then the sentence appears at the caret with a trailing space, and
      the Drop goes away. With the RTX 3090 this takes well under half a second. The clipboard
      still holds the sentinel; Win+V does not list the sentence.
- [ ] Notepad's title bar stays active the whole time and its caret keeps blinking: the Drop
      never takes focus.
- [ ] Dictate again within 30 seconds, starting to speak exactly as you press: the first word is
      complete (the take keeps the 300 ms before the press).
- [ ] Leave it alone for 70 seconds: the microphone-in-use icon goes away (the mic is let go of
      after a minute). The next dictation works; its very first syllable may be clipped.
- [ ] Hold right Ctrl for about 0.25 s saying "hi": the Drop says "Too short / Try again" for a
      few seconds, the ink still. Nothing typed.
- [ ] Hold right Ctrl in silence for two seconds: "No speech heard" (never made-up words).
- [ ] Two takes back to back: let go and hold again at once: both go in, the first complete.
- [ ] The Drop's look while dictating matches the Mac's (paper panel, the ink on its left, grey
      title over a darker line); Alt-Tab never lists it.

## 5. Where it cannot type

- [ ] Notepad run as administrator, caret in it, dictate: the Drop says "Can't type into this app
      / It runs as administrator; your words are in the Library". Nothing typed; the Library has
      the dictation.
- [ ] Settings > Privacy & security > Microphone: switch off "Let desktop apps access your
      microphone". Hold right Ctrl: the Drop says "Couldn't open the microphone". Switch it back
      on: the next take works (no restart).
- [ ] With a USB mic as the input: hold right Ctrl, start speaking, unplug it while still holding.
      The Drop says "Couldn't open the microphone"; what was said before goes in (or "Too
      short"); it never stays on "Listening". Plug it back; the next take works.

## 8. Optional: dictation latency on a quiet PC

The numbers in the step's report were taken while other things ran ("not a measurement"). For a
measurement, close other apps (Parsec, Adobe's services), then from `core` in the Developer
Command Prompt:

```
set INK_BENCH_DIR=<bench data>
cargo build --release -p ink-bench --features engine-llama,engine-silero,ink-engines/engine-llama-vulkan
target\release\ink-bench.exe latency --runs 20 --seconds 5
set GGML_VK_VISIBLE_DEVICES= 
target\release\ink-bench.exe latency --runs 20 --seconds 5
```

(The second run hides every Vulkan device: `set GGML_VK_VISIBLE_DEVICES=` followed by one space,
so it runs on the CPU as a PC without a GPU would.) Targets: p50 ≤ 350 ms, p95 ≤ 700 ms.

## Known limits (not failures)

- A PC without a Vulkan GPU dictates with Qwen3-ASR on the CPU: about 1.6 s from letting go to
  the text, against 0.35 s. That is the current decision, not a fault.
- No live words while holding the key yet (no live-partials engine on Windows in this build).
- The Drop's plain fallback panel (shown while the ink cannot draw) shows live words cut at their
  end, not their start.
- A 0.2 key stored as `fn` or `right_command` cannot be held on Windows: Settings says the key
  can't be used here, and another must be picked.
- The hook's own limits are in `S3.1-CHECKLIST.md` (a removed hook noticed within about 5 s of the
  next typing; right Alt with AltGr layouts; the secure desktop).
