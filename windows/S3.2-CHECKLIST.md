# S3.2 checklist: Parakeet on Windows, and the diarizer

What an SSH session cannot check: the live words on screen while you speak, dictation on a PC
without a GPU as it feels, and a real call's far end told apart. About twenty minutes at the PC,
signed in, after S3.5a's checklist. Note the date, the Windows build and the commit under Result.

Automated checks cover the logic: the live-partials scheme (`cargo test -p ink-engines --lib live`),
the router's choice without a GPU (`--test router`), a registry model's live words through a
meeting (`cargo test -p ink-ffi --test streaming`), and, with the model, Parakeet's accuracy, its
live finals at real time and the ONNX Runtime check (`--features engine-sherpa --test sherpa --
--ignored`, see that file).

## Setup

As S3.5a's, with sherpa-onnx and NeMo-Speech.cpp added. In a **Developer Command Prompt for VS**
(x64), from the repository:

```
cd core
set LIBCLANG_PATH=C:\Program Files\LLVM\bin
set CMAKE_GENERATOR=Ninja
set SHERPA_ONNX_DIR=<unpacked sherpa-onnx-v1.13.4-win-x64-shared-MD-Release-no-tts-lib>
set NEMO_SPEECH_DIR=<NeMo-Speech.cpp prefix from native/build-nemo-speech.sh>
cargo build --release -p ink-ffi --lib --features engine-llama,ink-engines/engine-llama-vulkan,ink-engines/engine-silero,ink-engines/engine-nemo,ink-engines/engine-sherpa
cd ..\windows
dotnet publish Inkwell\Inkwell.csproj -c Release -o %TEMP%\inkwell-app -p:InkCoreDir=%CD%\..\core\target\release\
copy ..\core\target\release\sherpa-onnx-c-api.dll %TEMP%\inkwell-app\
copy ..\core\target\release\onnxruntime*.dll %TEMP%\inkwell-app\
copy %NEMO_SPEECH_DIR%\bin\*.dll %TEMP%\inkwell-app\
```

(The publish copies only `ink_ffi.dll`; the engines' DLLs must sit beside `Inkwell.exe`, and
`onnxruntime.dll` there is the one that counts: Windows has an older one of its own.)

Models: S3.5a's folder, plus Parakeet: copy its four files (`encoder.int8.onnx`,
`decoder.int8.onnx`, `joiner.int8.onnx`, `tokens.txt`) into
`<models folder>\parakeet-tdt-0.6b-v3-int8\2bda32ec70b0\`, with a `.revision` file there holding
`2bda32ec70b097a55adaa07d9a7173915b43cc78` and nothing else (no line end). Nemotron-3-Diarization
the same way, from its registry row (`core/crates/ink-engines/src/rows.rs`).

## 1. Live words (Parakeet on the CPU)

- [ ] Hold right Ctrl and say a long sentence: words appear in the Drop while you speak, about
      half a second behind, and the newest word shows a moment later than the rest.
- [ ] Let go: the text in Notepad is Qwen3-ASR's (with the GPU), and the Drop's words were only
      a preview.
- [ ] A meeting (or `replay_meeting`): Live shows both sides' words as they are said.
- [ ] Without the Parakeet model installed: no live words, nothing else changes, and dictation
      still types its text.

## 2. Dictation on a PC without a GPU

- [ ] Quit, then start it with every Vulkan device hidden: `set GGML_VK_VISIBLE_DEVICES= ` (one
      space) before `%TEMP%\inkwell-app\Inkwell.exe`. Dictate a 5 s sentence: the text lands about
      half a second after letting go (Parakeet), where Qwen3-ASR on the CPU takes about two.
- [ ] Still with the GPU hidden, dictate for two minutes (toggle mode): the whole take lands
      (cut into windows of at most 90 s), not an error.
- [ ] The same, with the Parakeet model removed: the text still lands, after about two seconds
      (Qwen3-ASR on the CPU).

## 3. The far end told apart (with S3.5b's real calls)

- [ ] A call with two or more people on the far end: the finished record tells their voices
      apart, not one far-end voice.
