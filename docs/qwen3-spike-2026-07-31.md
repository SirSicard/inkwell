# Qwen3-ASR spike

**Date:** 2026-07-31
**Verdict:** It wins on accuracy by a clear margin and is fast enough. Recommend
shipping it as the accuracy tier, not as the default, and only after the
hotword lifecycle is designed properly rather than bolted on.

## Measured

Eight recordings of the owner's voice (Swedish-accented English), scored against
what was actually said. Every model biased with the same dictionary.

| Model | WER | Time (57s of audio) | Size | Languages |
|---|---|---|---|---|
| **Qwen3-ASR 0.6B int8** | **5.6%** | 9.2s | 941 MB | 30, incl. Swedish |
| Parakeet V2 int8 | 8.0% | 3.6s | 633 MB | English |
| SenseVoice | 9.3% | 1.7s | 241 MB | en, zh, ja, ko, yue |
| Whisper Turbo | 9.3% | 19.8s | 1.0 GB | 99 |
| Parakeet V3 int8 | 10.5% | 3.7s | 642 MB | 25 European |

Roughly 6x real time, so a 5-second dictation costs under a second. That is the
question that mattered going in, and the answer is that speed is not the
obstacle. Whisper Turbo is the one that is too slow to use.

## The dependency upgrade

sherpa-onnx 1.12.33 to 1.13.4 was the risk, since it swaps the prebuilt static
C++ libraries under every model. It compiled clean, 152 tests pass, and the
existing models still load and score within noise of their previous numbers
(Parakeet V3 moved 11.7 to 10.5, Whisper Turbo 8.6 to 9.3, on eight clips).

## Hotwords are not optional for this model

Without bias phrases Qwen3 scored 7.4% and produced "Inquil" and "Verso" for
Inkwell and Vercel: worse on proper nouns than Parakeet, which is the failure
the owner originally complained about. With them it scores 5.6% and gets both
right.

The catch is structural. Qwen3 takes bias phrases **at construction**, in its
model config, while Parakeet takes them **per utterance** on the stream. The
spike bridges that with a `hotwords.txt` beside the model, read at load. That
is a real mechanism, not a hack, but it means the engine must be rebuilt when
the dictionary changes, and nothing does that today. Shipping without solving
it would give users a dictionary that silently stops applying until restart.

## Determinism

Qwen3 decodes with a language model, so its config carries `temperature`,
`top_p` and `seed`. A dictation tool must return the same text for the same
audio. Pinned to temperature 1e-6 and seed 42, and verified: two full runs over
the corpus produced byte-identical output.

## Resolved after the spike

The hotword lifecycle below was built rather than deferred: saving the
dictionary now rewrites the phrase file for construction-time models and
rebuilds the engine, verified end to end (7.4% unaided, 5.6% with the
dictionary, same code path the app calls). `ab_models` gained `--no-hotwords`
so that comparison can be re-run rather than taken on trust; without it the
harness overwrote the file being tested and produced a meaningless result once
already.

## Recommendation

1. **Do not make it the default.** 941 MB against 633 MB, and 2.6x the decode
   time, for a gain that is real but measured on eight clips of one voice.
2. **Offer it as the accuracy tier**, described honestly: best measured
   accuracy, larger download, still comfortably fast, 30 languages including
   Swedish, which is the only model here that covers both the owner's languages.
3. **Design the hotword lifecycle first.** Rebuild the engine when the
   dictionary changes, or accept and document that dictionary edits need a
   restart under Qwen3.
4. **Re-measure on a larger corpus** before treating 5.6 against 8.0 as
   settled. Eight clips is a direction, not a benchmark.

## Not answered

Whether sherpa-onnx exposes Qwen3's streaming mode. The model card advertises
"streaming / offline unified inference", and if that is reachable it would let
one model serve both dictation and the live partials the streaming spike
designed, instead of a second 296 MB download.
